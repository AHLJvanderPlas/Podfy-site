What the API is

The PODFY Open API lets your own systems read records (proofs of delivery and QR reports), update their work status and manage the reference (asset) register. It is a JSON REST API for server to server use. There is no CORS: call it from your backend, never from a browser.

The Open API is part of PODFY Advanced. When it is not active for your brand, every call answers 403 feature_not_active. The specification is OpenAPI 3.1 and the reference below is generated from the same file.

Get an API key

A brand admin creates keys in the portal under Settings → Integrations → API keys. Give the key a name and choose its scopes. The key is shown once, so store it in your secrets manager. You can revoke a key at any time, and a revoked key stops working immediately.

  • records:read: read records
  • records:write: update records (also allows reading them)
  • references:read: read the reference register
  • references:write: create and change references (also allows reading them)

Base URL and authentication

The base URL is https://portal.podfy.net/api/v1. Send your key as a Bearer token in the Authorization header on every request. A key never works in a query parameter.

A missing, malformed, unknown or revoked key always gets the same answer, 401 invalid_key. A key without the required scope gets 403 insufficient_scope.

curl -H "Authorization: Bearer $PODFY_API_KEY" \
  "https://portal.podfy.net/api/v1/records?limit=10"

Live and test keys

Keys starting with pk_live_ see only production records. Keys starting with pk_test_ (QA records only) see only test records from qa.podfy.app, whose PODFY IDs start with QA-. The two environments never mix.

The reference register is shared with production, so test keys cannot create or change references (403 insufficient_scope). A record or reference of another brand, or a record of the other environment, answers 404 not_found, never 403.

Rate limit

Each key may make 600 requests per minute, counted in fixed one-minute windows. Every answer carries X-RateLimit-Limit, X-RateLimit-Remaining and X-RateLimit-Reset (unix seconds when the window ends).

Above the limit you get 429 rate_limited with a Retry-After header (seconds). Wait that long and try again.

Errors

Every error is JSON in the same shape: {"error":{"code":"…","message":"…"}}. Handle errors by the HTTP status and the code, not by the message text. Responses are never cached (Cache-Control: no-store). The full list of codes is in the reference below.

Pagination

List endpoints return {"data": [...], "next_cursor": "…"}. Pass next_cursor back as the cursor parameter to get the next page, until it is null. Cursors are opaque: do not build or change them. Records are listed newest first. The page size is set with limit (1 to 200, default 50).

POST /refunds/{id}/approve

Approve a refund Required scope: refunds:write

Moves a requested refund to approved (actor api:<key prefix>). Sends the webhook refund.approved to webhooks that subscribed to it by name (never to *). Any other status: 409 invalid_transition. The body is optional.

Needs refund requests active for the brand (part of Advanced), else 403 feature_not_active. pk_test_… keys see and change only refunds of QA records, pk_live_… keys only production refunds; anything else answers 404 not_found.

POST /refunds/{id}/result

Report the payout result Required scope: refunds:write

Your payment platform reports the result of an approved refund: paid or failed. Sends the webhook refund.updated to webhooks that subscribed to it by name. Idempotent: the same status again answers 200 with the stored refund and changes nothing. A result for a refund that is not approved (or a different result after a final one): 409 invalid_transition.

Needs refund requests active for the brand (part of Advanced), else 403 feature_not_active. pk_test_… keys see and change only refunds of QA records, pk_live_… keys only production refunds; anything else answers 404 not_found.
