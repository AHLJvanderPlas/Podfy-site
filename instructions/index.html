1. Site architecture overview

The PODFY marketing site (podfy.net) is hosted on Cloudflare Pages as a static site with server-side logic handled by Cloudflare Pages Functions (in the /functions directory). It is one of five repos in the Podfy ecosystem, but it is completely independent of the other four apps.

Repo / AppDomainDatabaseNotes
Podfy-site (this site)podfy.netpodfy-publicMarketing site, no user auth
Podfy-apppodfy.apppodfy-mainDriver upload interface
podfy-adminadmin.podfy.netpodfy-mainAdmin dashboard (JWT auth)
podfy-portalportal.podfy.netpodfy-mainCustomer portal (magic link)
Podfy-deliverydelivery.podfy.netpodfy-mainDelivery portal (magic link)

podfy-site connects only to the podfy-public D1 database. The production database (podfy-main) is not accessible from this site and contains no site data.

2. Database status, what is connected

The site uses one D1 database: podfy-public (ID: 8b8e12db-2a7d-47eb-8d12-8a548e71da64). It has three tables:

Site_Releases Active /api/releases, /changelog.rss, changelog page Add, edit, publish/unpublish release entries
Site_Form Active /api/contact (contact form), /api/subscribe (newsletter) Read submissions, update status and first_response
Site_Buyer Active, niche /api/pricing-factor, called from pricing page with ?code= URL param Add buyer segment keywords & custom pricing multipliers

3. Managing the changelog (Site_Releases)

The /changelog page fetches release entries from Site_Releases via GET /api/releases. The RSS feed at /changelog.rss also reads from this table.

Table columns

ColumnTypeNotes
idINTEGER PKAuto-incremented
release_dateTEXT (YYYY-MM-DD)Shown as the release date
versionTEXTe.g. v2.14.1, used as the changelog entry title
deployment_refTEXTInternal CF deployment ref (optional)
new_featuresTEXTOne bullet per line (newline-separated)
fixesTEXTOne bullet per line (newline-separated)
area_tagsTEXTComma-separated tags e.g. portal,app
is_publishedINTEGER (0/1)Only rows with is_published = 1 are shown publicly

Adding a new release via Wrangler CLI

wrangler d1 execute podfy-public --remote --command \
  "INSERT INTO Site_Releases (release_date, version, new_features, fixes, area_tags, is_published)
   VALUES ('2026-05-05', 'v2.15.0',
     'Guides section launched with 8 topic pages
Solutions section launched with 8 audience pages',
     '',
     'site,seo',
     1)"

Adding a new release via D1 Dashboard

  1. Go to dash.cloudflare.com → D1 → podfy-public
  2. Click Console tab
  3. Run an INSERT statement like the one above
  4. The changelog page fetches live: no redeploy needed

Drafting (not yet visible)

Set is_published = 0 to save a draft entry that won't show publicly. Set it to 1 when ready to publish.

4. Viewing contact submissions (Site_Form)

Contact form submissions (/contact page) and changelog newsletter subscriptions are stored in Site_Form. An internal email notification is also sent via Resend on each submission, but the D1 record is the persistent archive.

Table columns relevant to you

ColumnNotes
nameSubmitter name
emailSubmitter email (lowercase)
companyCompany name (from contact form)
sectorIndustry/sector selected, or changelog-subscription for newsletter sign-ups
messageFree-text message
source_pathURL path of the form that was submitted (e.g. /contact, /changelog)
statusnew → update to replied or closed when handled
first_responseTimestamp of first response (fill manually or via admin)
created_atWhen the form was submitted (ISO timestamp)

Viewing submissions

-- All new contact form submissions
SELECT id, name, email, company, message, created_at
FROM Site_Form
WHERE sector != 'changelog-subscription' AND status = 'new'
ORDER BY created_at DESC;

-- Changelog newsletter subscribers
SELECT id, name, email, created_at
FROM Site_Form
WHERE sector = 'changelog-subscription'
ORDER BY created_at DESC;

Marking as replied

UPDATE Site_Form SET status = 'replied', first_response = datetime('now') WHERE id = 42;

5. Custom pricing segments (Site_Buyer)

The pricing page supports a secret URL parameter: /pricing?code=KEYWORD. When a valid keyword is found in Site_Buyer, the pricing calculator uses a custom multiplier (the wtp_percent value). This is used for sales conversations, e.g. share a custom pricing URL with a high-value prospect.

Table columns

ColumnNotes
idAuto-incremented PK
segmentHuman-readable segment name (shown in pricing UI), e.g. Elite Shipper
keywordSecret URL parameter value, keep this private per prospect
wtp_percentPricing multiplier. 1.0 = standard price, 1.5 = 50% premium, 0.8 = 20% discount

Adding a custom prospect code

INSERT INTO Site_Buyer (segment, keyword, wtp_percent)
VALUES ('DHL Special', 'dhl2026secret', 1.25);

Then share the URL: https://podfy.net/pricing?code=dhl2026secret

Note: The keyword is treated as case-sensitive. Keep prospect-specific codes private, anyone with the URL can see the custom pricing.

6. Deployment workflow

All changes go through the qa branch first. Only Podfy-site's main branch is protected, direct pushes are rejected.

# 1. Make changes on qa branch
git checkout qa

# 2. Stage and commit
git add [files]
git commit -m "Your description"

# 3. Push, Cloudflare auto-deploys to qa (no QA Pages project for site yet)
git push origin qa

# 4. Open PR: qa → main on GitHub
# Visit: https://github.com/AHLJvanderPlas/Podfy-site

# 5. Merge PR → Cloudflare auto-deploys to production (podfy.net)

D1 changes (changelog entries, form status updates) take effect immediately without redeployment, the site fetches live data from the database on every request.

10. Companies & themes viewer

Loads live from https://podfy.app/api/brands (D1-backed). Shows all customer slugs with their brand settings. Color values are rendered with their actual colour as the cell background. Logo, email_recipients and notes_internal columns are hidden.
